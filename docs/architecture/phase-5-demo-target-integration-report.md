* **Scenario A — Authentication-Failure Threshold:** **PASS**

## G. Security Review

1. **Loopback & Destination Confinement:** Attack simulator strictly enforces destination whitelist (`localhost`, `127.0.0.1`, `0.0.0.0`, `::1`). External targeting throws immediate security violations.
2. **Zero Shell Metacharacter Execution:** Containment targets are validated strictly through `ipaddress.ip_address` or regex token identifiers. Injection characters (`;`, `&`, `|`, `` ` ``) fail closed immediately.
3. **Mandatory Human-in-the-Loop:** Active responses cannot execute directly without an explicit state transition through `APPROVED` by an authenticated operator session.
4. **Tamper-Evident Audit Trail:** Every action start, success, and failure appends a SHA-256 hash-chained immutable audit log entry.
5. **No AI/LLM or OSINT Dependencies:** Investigations, detections, and response proposals rely purely on deterministic rules, authoritative event IDs, and validated target schemas.

## I. Known Limitations

1. **In-Memory Volatility:** In the current phase, target security state (blocklist, disabled sessions) is stored in thread-safe process memory. Long-term production deployments require Redis or Postgres persistence.
2. **Local Loopback Simulation:** Simulator tests run against local loopback ports or in-memory ASGI test clients. Physical network interface firewall rules (e.g. `iptables` / Windows Defender Firewall) are simulated at the application gateway middleware layer.
