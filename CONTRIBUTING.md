# Contributing to GASHA

Thank you for contributing to GASHA! This repository is organized as a Turborepo monorepo designed for high-velocity, parallel collaboration across **Backend**, **Frontend**, **Cybersecurity**, **AI / Security Intelligence**, and **DevOps** engineers.

---

## 1. Team Ownership Boundaries

| Team / Role | Workspace / Folder | Responsibilities |
| :--- | :--- | :--- |
| **Backend Engineers** | `apps/api/app/` (`api/`, `digital_twin/`, `discovery/`, `risk/`, `detection/`, `response/`, `adaptive/`) | FastAPI API surface, graph traversals, deterministic detection execution, risk engine, allowlisted response actions, adaptive loop state transitions. |
| **Frontend Engineers** | `apps/web/` (`app/`, `components/`, `hooks/`, `lib/`, `stores/`) | Next.js dashboard, React Flow graph canvas, real-time WebSocket state management, incident triage drawers. |
| **Cybersecurity Researchers** | `packages/detection-rules/`, `docs/cybersecurity/`, `apps/demo-target/vulnerabilities/` | Security source-of-truth: detection rules & signatures, attack scenarios, telemetry specs, safe test fixtures. |
| **AI Engineers** | `apps/api/app/ai/`, `docs/ai/` | Investigation orchestration, prompt templates, evidence grounding verification, model provider adapters, and evaluation benchmarks. |
| **DevOps Engineers** | `infra/`, `scripts/`, `.github/`, root configs | Multi-container Docker topologies, CI/CD pipelines, Vercel/GitHub integration configuration, database provisioning. |

## 2. Branch Naming Conventions

All branch names must follow standard team prefixes:

```bash
feature/backend-<short-description>
feature/frontend-<short-description>
feature/cyber-<short-description>
feature/ai-<short-description>
feature/devops-<short-description>

fix/<team>-<short-description>
docs/<short-description>
refactor/<team>-<short-description>
test/<team>-<short-description>
```

### Examples
- `feature/backend-digital-twin-graph`
- `feature/frontend-attack-path-canvas`
- `feature/cyber-rule-credential-stuffing`
- `feature/ai-grounded-investigation-prompt`
- `feature/devops-docker-compose-postgres`
- `fix/backend-cycle-detection`

## 3. The 7 Golden Collaboration Rules

1. **Work Inside Your Assigned Area**: Stay within your module boundaries. Coordinate before changing cross-module interfaces.
2. **Contracts First**: Shared contracts in `packages/contracts` and `apps/api/app/schemas/` are the single source of truth. Any contract modification must be approved by affected leads.
3. **No Duplicate Models**: Do not define custom ad-hoc interfaces or schemas inside feature folders. Always import from `@gasha/contracts` or `app.schemas`.
4. **Never Commit Secrets**: Never commit `.env`, API keys, private tokens, or real credentials. Use `.env.example` as a sanitized template.
5. **No Unrelated Changes**: Keep pull requests small, focused, and well-documented.
6. **No Mock Security Logic in Frontend**: Frontend must render state received from backend APIs. Never hardcode mock detections or mock risk calculations in the frontend.
7. **Strict Evidence Grounding for AI**: Any AI reasoning must be grounded on concrete `Evidence` objects generated by the Investigation Engine. If evidence is lacking, return *"Insufficient evidence"*.

---

## 4. Pull Request Process
1. Rebase your branch on `upstream/main` or `upstream/foundation`.
2. Ensure linting and tests pass.
3. Fill out the PR template in `.github/pull_request_template.md`.
4. Request review from the appropriate team lead.
